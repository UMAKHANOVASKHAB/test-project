# Планка качества (CONSTRAINTS)

Договор для людей и для Claude. Опускать планку молча нельзя: любое ослабление
только с согласия владельца и с записью сюда, с причиной.

## Деньги и данные
1. Цены, итог, скидки и штампы считает только сервер по `apps/web/src/data/menu.json`. Суммы от клиента игнорируются.
2. Пользователь определяется только по проверенной подписи Telegram (`Authorization: tma <initData>`). userId из запроса не принимается.
3. Всё, что меняет деньги или штампы, пишется одной транзакцией базы.
4. Каждая отправка заказа несёт `clientKey`: повтор не создаёт второй заказ.
5. База лежит на постоянном диске (Railway Volume `/data`), не в `/tmp`.

## Код
1. `npm run lint`, `npm test`, сборка web и api проходят до push. Это же проверяет GitHub Actions (`.github/workflows/ci.yml`).
2. Тесты не отключаются, не удаляются и не ослабляются ради зелёной галочки. Нет `it.skip`, `@ts-ignore`, `eslint-disable` без комментария с причиной.
3. Любая ошибка в логике денег или штампов сначала воспроизводится тестом, потом чинится.
4. Новые пакеты: версия из реестра npm, пакет популярный и именно тот. Работа с библиотекой сверяется с официальной документацией.
5. Секреты (токен бота и т.п.) только в переменных Railway, никогда в коде и в git.

## Порог по умолчанию
- Логика денег, штампов, подписи: покрыта тестами на каждый найденный случай.
- Ответ сервера на заказ: без ошибок 5xx в логах Railway после деплоя.
