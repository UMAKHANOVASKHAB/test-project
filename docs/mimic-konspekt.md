# Конспект: Mimic (разбор чужого приложения в Python-код)

Источник: короткое видео (30.09.2026) и README репозитория https://github.com/littledivy/mimic (MIT, около 1,6 тыс. звёзд на 30.09.2026).

## Что это
Инструмент, который превращает мобильное приложение в Python-библиотеку:
1. Телефон ходит в интернет через прокси mitmproxy на Mac, Mimic записывает запросы приложения.
2. Из записи вытаскивает данные входа: токен, id устройства, сессию, cookies.
3. Claude читает записанные запросы и пишет клиент на Python с понятными методами.

Команды: `sh install.sh`, `mimic doctor`, `mimic record`, `mimic hosts`, `mimic learn <host>`, `mimic gen <host>`.
Нужно: Mac, iPhone с настройкой прокси, ключ Claude API, менеджер пакетов uv.
Не работает с certificate pinning (банки, Instagram; есть обход `mimic unpin` через Frida) и с токенами DPoP.

## Где можно, где нельзя
- Можно: свои аккаунты и свои данные, автоматизация своих дел, проверка своего же приложения.
- Нельзя: чужие аккаунты, обход защиты и платных функций, нарушение правил сервиса. Это обман и присвоение чужого (харам), по закону неправомерный доступ к информации (ст. 272 УК РФ).

## Главный урок для наших проектов
Любой запрос мини-аппа или приложения можно увидеть и отправить вручную (Mimic, curl, Postman). Поэтому сервер не должен верить ничему, что считает клиент:
- кто пользователь: только из проверенной подписи (в Telegram это initData, проверка по HMAC с токеном бота);
- цены, сумма, скидки, бонусы: только по меню и данным на сервере;
- чужие данные: отдавать только владельцу, id берётся из подписи, а не из адреса запроса;
- секреты (токены, ключи) никогда не кладём в код мини-аппа.

Применено в 9 bar coffee: `apps/api/src/auth.ts` (проверка initData), `apps/api/src/pricing.ts` (цены и штампы на сервере).
Чек-лист для каждого нового сайта или бота: пройти эти 4 пункта до запуска.
