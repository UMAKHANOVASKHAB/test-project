# 9 bar coffee: как устроено и что делать, если сломалось

Памятка для владельца проекта и для Claude в новых сессиях.

## Что где
- Бот: @ninebar_coffee_05bot (токен в @BotFather, команда /token).
- Сервер: Railway, проект production, сервис ninebar-coffee.
- Адрес мини-аппа: https://ninebar-coffee-production-4d6a.up.railway.app
- Код: GitHub fhkgm23-cpu/test-project, ветка main. Любой push в main сам пересобирает сервис на Railway.

## Переменные на Railway (Variables)
| Имя | Значение | Зачем |
|---|---|---|
| BOT_TOKEN | токен от @BotFather | без него бот молчит, сайт работает |
| ADMIN_CHAT_ID | chat id получателя заказов | кому приходят заказы; главнее команды /admin |
| DB_FILE | /tmp/ninebar.db (сейчас) или /data/ninebar.db (с диском) | где лежит база |
| WEBAPP_URL | не нужна | адрес берётся из RAILWAY_PUBLIC_DOMAIN |

## Известные ограничения
- База в /tmp: при каждом перезапуске и деплое стираются заказы, штампы и нумерация (снова №101). Лечится диском: Volume с путём /data и DB_FILE=/data/ninebar.db.
- Railway Trial ограничен по кредитам и сроку. Когда закончится, сервис остановится: нужен тариф Hobby.
- /admin может отправить любой, но если задан ADMIN_CHAT_ID, заказы всё равно идут туда.

## Если не работает
1. Бот не отвечает на /start. Railway → Deployments: статус Crashed или Active?
   - Crashed: открыть деплой → Deploy Logs, прислать последние строки.
   - Active: Deploy Logs, искать «Бот не запустился». 401 или 404 значит неверный токен (перевставить BOT_TOKEN). 409 Conflict значит этот же бот запущен где-то ещё (другой сервер или конструктор вроде PuzzleBot).
2. Отвечает чужой бот (PuzzleBot и т.п.): токен подключён к другому сервису, нужен отдельный бот.
3. Мини-апп не открывается: открыть адрес в браузере. Если не грузится, сервис лежит (см. п. 1) или закончился Trial.
4. Заказы не приходят бариста: проверить ADMIN_CHAT_ID; бариста должен хотя бы раз нажать /start у бота.
5. Всё сломалось после правки кода: Railway → Deployments → у последнего рабочего деплоя три точки → Redeploy (откат).
