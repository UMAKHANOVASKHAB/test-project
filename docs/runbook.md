# 9 bar coffee: как устроено и что делать, если сломалось

Памятка для владельца проекта и для Claude в новых сессиях.

## Что где
- Бот: @ninebar_coffee_05bot (токен в @BotFather, команда /token).
- Сервер: Railway, проект production, сервис ninebar-coffee.
- Адрес мини-аппа: https://ninebar-coffee-production-4d6a.up.railway.app
- Код: GitHub fhkgm23-cpu/test-project, ветка main. Любой push в main сам пересобирает сервис на Railway.

## Переменные на Railway (Variables)
| Имя | Значение | Зачем |
|---|---|---|
| BOT_TOKEN | токен от @BotFather | без него бот молчит, сайт работает |
| ADMIN_CHAT_ID | chat id получателя заказов | кому приходят заказы; главнее команды /admin |
| DB_FILE | /tmp/ninebar.db (сейчас) или /data/ninebar.db (с диском) | где лежит база |
| WEBAPP_URL | не нужна | адрес берётся из RAILWAY_PUBLIC_DOMAIN |
| BACKUP_CHAT_ID | id закрытого канала копий (вида -100…) | куда каждую ночь уходит копия базы; если не задан, копия идёт в ADMIN_CHAT_ID |
| BACKUP_HOUR_UTC | 0 (по умолчанию) | час отправки копии по UTC; 0 это 03:00 по Москве |

## Известные ограничения
- База в /tmp: при каждом перезапуске и деплое стираются заказы, штампы и нумерация (снова №101). Лечится диском: Volume с путём /data и DB_FILE=/data/ninebar.db.
- Railway Trial ограничен по кредитам и сроку. Когда закончится, сервис остановится: нужен тариф Hobby.
- Если задан ADMIN_CHAT_ID, команда /admin ничего не меняет. Без переменной получателя закрепляет только первый, кто напишет /admin.

## Безопасность заказов
- Кто заказывает, сервер узнаёт по подписи Telegram (initData, проверка в `apps/api/src/auth.ts`). Для проверки нужен тот же BOT_TOKEN.
- Цены, сумму и штампы считает сервер по `apps/web/src/data/menu.json` (`apps/api/src/pricing.ts`). Меняете цены в меню: сервер подхватит после деплоя.
- Заказ принимается только из Telegram (с подписью). В обычном браузере меню видно, но заказ не отправится.
- Время самовывоза сервер проверяет сам: только в часы работы из `menu.json` (`shop.hours`) и не раньше текущей минуты по Москве (`shop.timezone`). Заказ на 03:00 или на прошедшее время не пройдёт.
- Один гость может сделать не больше 5 заказов за 10 минут. Счётчик живёт в памяти и обнуляется при перезапуске.
- Что видит гость при ошибке: «Сессия устарела» (мини-апп открыт больше суток, закрыть и открыть заново), «Это время уже прошло», «Кофейня в это время не работает», «Слишком много заказов подряд», «Проверьте интернет» (только при сбое связи).
- Галочка «Использовать бесплатный кофе» ставится сама, когда подарок доступен. Гость может её снять.
- Сколько штампов до бесплатного кофе, задаёт `shop.loyalty.stampsForFree` в `menu.json`: оттуда берут и мини-апп, и приветствие бота.

## Заказы у бариста
- Под каждым заказом три кнопки: «Готов» (гостю приходит «можно забирать»), «Выдан», «Отменить».
- Штампы начисляются только по «Выдан». Не пришёл гость: нажать «Отменить», штампов не будет.
- Нажимать кнопки можно только в чате из ADMIN_CHAT_ID. Повторное «Выдан» штампы не задваивает.
- Заказы, сделанные до этой версии, считаются выданными (штампы за них уже были).

## Резервные копии базы
- Каждую ночь в 03:00 по Москве сервер делает копию базы и присылает файл ninebar-ДАТА.db в закрытый Telegram-канал (BACKUP_CHAT_ID).
- Как узнать id канала: создать закрытый канал, добавить туда бота администратором с правом публикации, написать в канале /id. Бот ответит числом вида -100…, его вставить в BACKUP_CHAT_ID.
- Копия по требованию: владелец (чат из ADMIN_CHAT_ID) пишет боту /backup.
- Восстановление: владелец пересылает боту файл копии из канала и в подписи пишет /restore. Бот сначала пришлёт копию текущей базы (на случай ошибки), потом перезапустится уже с базой из файла.
- /backup и /restore работают только при заданной переменной ADMIN_CHAT_ID. Команда /admin на них не влияет.
- Без Volume /data восстановление не переживёт следующий деплой: сначала диск, потом копии.

## Сборка
- Dockerfile ставит библиотеки строго по `package-lock.json` (`npm ci`) и убирает из образа инструменты разработки. Добавили библиотеку: обязательно закоммитьте и обновлённый `package-lock.json`.
- Проверки перед отправкой в main: `npm test`, `npm run lint`, `npm run build -w apps/web`, `npm audit --omit=dev`.

## Если не работает
1. Бот не отвечает на /start. Railway → Deployments: статус Crashed или Active?
   - Crashed: открыть деплой → Deploy Logs, прислать последние строки.
   - Active: Deploy Logs, искать «Бот не запустился» и «Ошибка бота». «Ошибка бота» значит, что одно сообщение не обработалось, но бот продолжает работать. 401 или 404 значит неверный токен (перевставить BOT_TOKEN). 409 Conflict значит этот же бот запущен где-то ещё (другой сервер или конструктор вроде PuzzleBot).
2. Отвечает чужой бот (PuzzleBot и т.п.): токен подключён к другому сервису, нужен отдельный бот.
3. Мини-апп не открывается: открыть адрес в браузере. Если не грузится, сервис лежит (см. п. 1) или закончился Trial.
4. Заказы не приходят бариста: проверить ADMIN_CHAT_ID; бариста должен хотя бы раз нажать /start у бота.
5. Всё сломалось после правки кода: Railway → Deployments → у последнего рабочего деплоя три точки → Redeploy (откат).
