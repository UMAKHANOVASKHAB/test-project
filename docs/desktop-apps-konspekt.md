# Конспект: настольные приложения на заготовке + Claude Code и продажа без сайта

Источник: англоязычное видео автора «Desktop App Starter» (октябрь 2026), расшифровано и сверено по кадрам. Цифры и сервисы проверены поиском 19.10.2026, всё неподтверждённое помечено.

## Главные идеи видео
1. **Ниша.** Почти все делают веб-приложения, а настольные (desktop) почти никто. Настольному приложению не нужны хостинг, сервер и база: оно работает на компьютере покупателя, значит нет ежемесячных расходов.
2. **Секрет скорости: заготовка (boilerplate).** Не писать с нуля, а взять готовый каркас, где уже есть: окно, темы, настройки, хранение API-ключа, 20+ готовых компонентов, сборка установщиков для Windows, macOS и Linux. Экономит время и токены.
3. **Главный файл заготовки: CLAUDE.md.** Правила, которые агент читает до кода: где что лежит, «как сделать X» (добавить экран, настройку, уведомление, вызов Claude), жёсткие правила архитектуры. Тогда агент не выдумывает, а собирает из готовых блоков по образцу.
4. **Стек из видео:** Electron 41, React 19, TypeScript 5.9 strict, Tailwind CSS 4, electron-builder (NSIS для Windows, DMG для macOS, AppImage и deb для Linux), Zod для проверки данных между процессами, react-hook-form.
5. **Правила архитектуры (взять себе):** граница процессов неприкосновенна (интерфейс не лезет в файлы и сеть напрямую); preload открывает только конкретные функции, по одной на канал; модули функций изолированы друг от друга; все данные между процессами проверяются схемой.
6. **Примеры:** «уборщик рабочего стола» за 24 минуты одним промптом (Claude раскладывает файлы по группам и объясняет почему); «анализатор диска» за 39 часов (карта диска «тёплое / замёрзшее», объяснение, что можно удалить; только чтение, удаляет сам человек). Агенты работали ночью.
7. **Решать маленькую реальную проблему,** лучше свою: если мешает тебе, мешает и другим.
8. **Строить публично.** Одна площадка (у автора X), каждый день или каждую функцию короткое видео. Видео тоже делает Claude Code. Сначала никто не смотрит, это нормально. К релизу уже есть первые тестировщики и отзывы. Собирать список ожидания (почта).
9. **Продажа без сайта:** загрузить установщик на Gumroad, поставить цену, продавать. Пиратства не бояться: ломают даже Adobe и Microsoft.

## Поправки под нас (важно)
- **Пользователь работает с телефона.** Настольное приложение не запустить и не проверить на телефоне. Нужен компьютер с Windows или Mac хотя бы для проверки, либо собираем в GitHub Actions и даём тестировщикам.
- **Gumroad и Россия.** Выплаты идут через Stripe; подтверждения, что продавец из РФ может получать выплаты, не нашёл (не проверено, скорее нет). Покупатели с российскими картами там тоже не платят. Для рынка РФ: Продамус, ЮKassa, Boosty, свой бот с оплатой через СБП. Для зарубежа нужен продавец с картой и документами страны, где Stripe работает (например, Саудовская Аравия, ОАЭ).
- **Claude внутри приложения.** Anthropic API официально не работает в РФ. Для покупателей из РФ предусматривать другой ИИ (YandexGPT, GigaChat) или работу без ИИ. Ключ API хранить только в системном хранилище (safeStorage), не в коде.
- **Подпись приложения.** Без цифровой подписи Windows SmartScreen и macOS Gatekeeper пугают покупателя предупреждением. Подпись платная (Apple Developer от 99 $ в год, сертификат Windows). Цены проверять перед заказом.
- **Персональные данные.** Если приложение что-то отправляет на сервер, применять `docs/legal-compliance-prompt.md`.
- **Шариат.** Продажа программ халяль, если продукт не служит хараму (азартные игры, риба, обман, непристойное). Цену и что входит в покупку писать честно, без скрытых списаний (гарар).

## Промпт: новое настольное приложение (вставлять в начале задачи)

Мы делаем настольное приложение на продажу. Действуй по шагам.
1. Проблема: одна маленькая реальная задача, для кого, почему они заплатят. Если не ясно, задай мне вопросы по одному.
2. Заготовка: если в репозитории нет `apps/desktop-starter`, сначала собери её: Electron + React + TypeScript strict + Tailwind + electron-builder, версии пакетов бери из npm, не по памяти. В заготовке: окно, светлая и тёмная тема, настройки, безопасное хранение ключа (safeStorage), уведомления, диалог выбора файла и папки, проверка данных Zod, установщики Windows / macOS / Linux, CLAUDE.md с разделом «как сделать X» и жёсткими правилами архитектуры (contextIsolation включён, nodeIntegration выключен, preload открывает только нужные функции).
3. Функция: собери её из готовых блоков заготовки, ничего не изобретай. Опасные действия (удаление, перезапись) только после подтверждения человеком.
4. Проверка: тесты, сборка, запуск; скриншоты для меня. Не пиши «работает», пока не проверил.
5. Продвижение: после каждой готовой функции дай текст поста и сценарий короткого видео (15–30 с) для одной площадки.
6. Продажа: предложи площадку под страну продавца и покупателя (см. поправки выше), текст страницы товара, цену и проверку юридических рисков.

## Что из этого берём для заказной работы
Тот же принцип заготовки работает и для мини-аппов: 9 bar coffee уже готовая заготовка «предзаказ для кофейни / пекарни / шаурмы». Новый клиент = смена меню, цветов и реквизитов, а не код с нуля.
